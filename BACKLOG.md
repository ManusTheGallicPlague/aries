# ARIES — Backlog & regole per le sessioni cloud

Questo file è la **memoria condivisa** tra le sessioni cloud che migliorano ARIES.

**Ciclo di ogni run:** leggi questo file → prendi l'item in cima a **"Da fare"** non ancora fatto → implementalo **per intero con il suo benchmark** → `python3 aries.py bench` deve passare → commit su `main` → sposta l'item in **"Fatto"** (una riga + il senso) → aggiungi eventuali idee nuove. **Un solo incremento solido per run.**

## Dottrina ARIES (non negoziabile)
- **Ground truth:** i fatti li produce il codice, con la prova accanto. L'LLM resta un interprete **opzionale** e debole. **Non** trasformare ARIES in un agente-LLM autonomo: è la scommessa opposta, già scartata misurandola.
- **Ogni lane attiva nasce col suo benchmark a due facce**: vero positivo **e** vero negativo, in `bench_vuln.py` + `aries.py` (`cmd_bench`). Mai committare se `aries bench` peggiora. *Eccezione:* `dom-xss` richiede Playwright, che in cloud può mancare → quella lane è esente; tutte le altre restano verdi, e una lane nuova aggiunge il suo **+2**.
- **PoC per ogni finding VULNERABILE:** usa `core.as_curl(...)` nel campo `repro` (token Bearer mascherati con `$TOKEN`, il JWT non entra nel referto).
- **Confine:** mai attaccare host esterni. Si sviluppa e si valida **solo** contro il fixture locale (`bench_vuln.py`, `127.0.0.1`). L'`ALLOWLIST` in `config.py` resta.
- **Onestà:** dichiara i limiti, non gonfiare i risultati, niente detection finte.
- **Stile:** lane piccole, stdlib-first, docstring/commenti in italiano come le esistenti.
- **In cloud** `semgrep`/`trivy`/`nuclei`/`ffuf`/`playwright` potrebbero mancare: preferisci lavoro in **puro Python** (tutti e 4 gli item prioritari lo sono). Se un item ha bisogno di un tool assente, prova a installarlo; se non riesci, saltalo e prendi il prossimo, senza rompere il bench.

## Fatto
